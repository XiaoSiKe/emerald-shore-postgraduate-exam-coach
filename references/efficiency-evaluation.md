# 考研效率评估系统

在用户问“最近学得有没有用”“为什么每天很忙却没进步”“这一周效率如何”，或执行周复盘时读取。

## 先定义效率

效率不是学习时长，也不是把多个指标揉成一个漂亮总分。它是：有限时间是否稳定转化为可验证的独立表现，并减少同类错误。本系统不生成伪科学综合分。

运行：

```bash
python emerald.py efficiency WORKSPACE --days 7
```

默认看最近 7 天，可在 1–90 天之间调整。输出写入 `.emerald-shore/efficiency.md`。

## 五个维度

1. **执行**：计划任务实际完成多少。低于 60% 时先判断任务与现实容量是否错配，不急着批评方法或人格。
2. **有效证据**：是否真的发生来源题、闭卷输出或限时检查点。只看课、看答案、整理桌面不能单独算掌握证据。
3. **独立答题质量**：`correct`、`partial`、`wrong` 的分布。练习量增加但正确率持续偏低，说明需要缩小缺口，而不是继续堆题。
4. **错因复发**：知识、识别、推理、步骤、粗心或时间压力是否重复出现。同一错误反复发生，比错题总数更值得优先处理。
5. **检查点转化**：日常训练是否进入同口径限时表现。没有可比较检查点时，只能说局部训练在发生，不能宣布总分效率提高。

## 诊断顺序

按顺序判断，只给当前最上游的问题：

| 诊断 | 含义 | 下一步 |
|---|---|---|
| 证据不足 | 记录太少，不能评价 | 完成一次任务和一次闭卷/限时检查 |
| 容量错配 | 执行率低，计划没有稳定发生 | 缩小任务，保留一个主攻 |
| 输入偏重 | 有学习时间，但没有验证 | 把下一次学习改成输出或做题 |
| 正确率缺口 | 已经练了，但独立结果偏低 | 停止堆题，定位第一个关键错因 |
| 错因复发 | 同类错误重复出现 | 只修一个重复错因并无提示复测 |
| 缺少检查点 | 局部训练有证据，但无法判断考试转化 | 安排同口径限时检查点 |
| 闭环稳定 | 执行、训练与检查点都已发生 | 保持主攻，只看趋势和重复错因 |

诊断不是人格标签，也不是永久结论。一次考试发挥失常、临时生病或课程周变化，都可能改变短期数据；需要结合真实情境解释。

## 不制造假精确

- 不输出“综合效率 87 分”之类的总分；不同维度不能假装等价。
- 不把题目数量直接当产出；三道能定位缺口的题，可能比三十道机械重复更有效。
- 不把坐在图书馆的时间等同于学习时间。椅子确实很努力，但它暂时还不能替你参加初试。
- 不用一天的数据推断能力；至少观察多个训练事件或同口径检查点。
- 不用他人的进度作为分母。效率只比较你的时间投入、证据质量和表现变化。

## 学生先解释，教练再判断

展示面板后先问学生：“你从这些数据里看到了什么？”学生的解释属于自我调节训练。教练随后补充被忽略的模式、校正过度乐观或灾难化解释，并一起确定一个“下周怎么学”的策略目标，而不只是“下周多学十小时”。

## 证据边界

此模块结合形成性评价、自我调节学习、刻意练习中的反馈原则和学习分析思路，但不声称这些少量本地指标可以预测最终录取。日志只能说明被记录的行为；未记录的学习、题目难度差异和考试状态仍是限制。
