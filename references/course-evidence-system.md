# 课程骨架、材料证据与自测系统

在用户提供混合资料、目标院校专业课、需要整理课程结构、生成专题卡、使用图示或连续答不出题时读取。

## 1. 一次稳定一个主攻科目

可以先粗分多科材料，但不要同时生成多门科目的完整冲刺包。优先处理当前主要矛盾；主攻科目至少形成可信课程骨架、一个高价值专题和一次可判定训练后，再扩展下一科。

这不是忽略其他科目。到期复习和最多两个维持任务继续保留，防止“单科沉没”。

## 2. 材料先分流，再进入知识系统

不要仅凭文件名猜归属。结合目录、标题、可见正文、院校、科目代码、年份和材料类型，给出归类置信度：

- `high`：科目与材料身份清楚，可以绑定科目；范围或题型证据明确时才绑定专题。
- `medium`：可以暂归某科，但不得直接绑定专题，也不能单独决定专题权重。
- `low`：保持未绑定并标记待确认，不能进入来源题训练。

原始文件保持只读。所谓“分流”是状态中的明确分类与置信标记，不擅自移动用户资料。调用 `ingest --classification-confidence` 记录判断。

## 3. 先建课程骨架，再压缩重点

课程结构使用“科目 → 章节 → 专题 → 来源题”四层：

1. 用官方大纲、指定教材目录或可靠课程范围确定科目和章节。
2. 用真题分布、官方说明、用户材料和最近错误确定专题权重。
3. 用 `topic add --chapter` 建立专题，不从自由联想直接生成“重点”。
4. 题目必须回链到来源与位置，训练结果再回流专题掌握度。

课程骨架不需要覆盖所有细枝末节。它的作用是回答“范围在哪里、当前打哪一块、哪份证据支持这个判断”。

## 4. 目标院校资料单独分级

公开网络上的同校资料既不等于官方范围，也不等于目标年份真题。只有同时记录以下匹配依据，才能使用 `target_school_open`：

- 目标院校明确匹配；
- 科目名或科目代码匹配；
- 材料类型清楚，例如公开真题、样题、作业、课程页面或复习资料；
- 年份、学期或更新时间尽量可追溯；
- URL 或仓库位置可回查。

调用 `ingest --evidence-level target_school_open --match-note ...` 保存匹配依据。若它与官方大纲、招生目录或用户确认的参考书冲突，以官方信息和用户明确材料为准，并展示冲突。

证据只影响它能支持什么结论：目标院校公开题可以帮助判断题型风格，不能凭相似主题宣布“今年必考”。

## 5. 专题卡必须能直接开始学习

专题卡不是美化后的目录。每张卡至少让学生立即完成四件事：

1. **闭卷写什么**：定义、公式、框架或评分点。
2. **遇题怎么做**：识别信号、方法选择和最短步骤。
3. **哪里容易错**：来自错题、真题或可靠材料的具体误区。
4. **怎样自测**：一道先不显示答案的题，以及通过标准。

普通情况保持少量文件或聊天卡片，不拆成难以导航的几十个小文件；考前 24 小时可以压缩为一张速查表，但仍保留来源与自测入口。

## 6. 可视化只解决真正的空间或关系障碍

区域、方向、法向、坐标变换、时间线、论证结构、概念依赖或流程关系难以仅靠文字理解时，使用最简单的 ASCII、Mermaid、表格或示意图。图必须帮助方法选择或回忆；纯装饰不算学习产出。

## 7. 短轮自测与熔断

互动仍坚持一次一题。一个诊断轮最多围绕同一薄弱层连续推进少量问题，依次定位：

- 定义或事实缺失；
- 公式、框架或关键词提取失败；
- 题型/设问识别错误；
- 推理、步骤或表达不稳定；
- 时间压力下无法完成。

连续三次 `wrong`/`partial`，或学生明确表示整块不会时，停止继续加题。回到专题卡，补最小概念、一个样例和一次闭卷复述，再用替代题重新测试。熔断是减少无效挫败，不是宣布放弃该专题。

## 8. 新材料只更新受影响部分

后续新增资料先判定为“新增、替代、可能重复、待确认”。SHA-256 相同的内容不重复建库；若同一材料获得了更可靠的科目、专题或匹配证据，重新 `ingest` 并显式使用 `--replace-metadata`，只更新绑定与证据元数据。没有该开关时保留旧证据等级，避免默认参数静默降级官方或真题来源。

新资料改变旧结论时，明确指出：哪条范围/权重判断被修订、置信度升高还是降低、哪些专题卡或自测需要重做。不要因为增加一份文件就全量推倒学生已经稳定的系统。
