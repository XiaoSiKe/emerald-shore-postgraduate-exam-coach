# 诊断与规划

首次使用只收集会改变计划的信息。若用户已给出，不重复询问。

## 最小诊断

1. 考试日期、目标院校和目标专业（院校/专业尚未确定时可空，但要标为待决策）。
2. 工作日与周末的现实可用时间、固定课程/实习/通勤，以及睡眠底线和常用学习地点。
3. 每科满分、最近一次限时成绩、目标分。
4. 每科名称、科目代码（如有）和主要任务类型：记忆、理解、计算、写作、语言或限时输出。
5. 可用大纲、教材、课程、真题、错题和模考记录。

缺少最近成绩时，用 30–60 分钟闭卷诊断代替主观“感觉”；没有任何测验时，当前分只是低置信基线。

## 建档顺序

1. 调用 `init` 创建本地状态；已知时同步记录 `--target-school` 与 `--target-major`。
2. 调用 `routine set` 区分工作日/周末容量，保存固定安排、睡眠底线和常用学习地点。
3. 每科调用一次 `subject add`；专业课或统考科目有代码时传 `--code`。只有用户能合理估算达标成本时才传 `--estimated-hours`。
4. 根据官方范围、真题分布和最近表现，按章节为高价值内容调用 `topic add --chapter`。`weight` 是科目内相对权重；`mastery` 必须来自闭卷/限时证据；`confidence` 表示证据可靠性。
5. 有材料则先判断归类置信度再 `ingest`；对真题使用 `past_paper`，对官方大纲使用 `official`，对匹配清楚的目标院校公开资料使用 `target_school_open` 并记录 `--match-note`。
6. 调用 `plan`，把主攻科目、主攻专题和第一任务翻译成简洁中文。

不要强迫学生一次填长问卷。信息不全但可安全前进时，声明假设并立即给一个诊断动作。

## 阶段默认值

- 91 天及以上：补基础、知识地图、复习队列。
- 46–90 天：专题突破、混合练习、每周检查点。
- 15–45 天：真题限时、错因修补、输出节奏。
- 1–14 天：错题和闭卷回忆、答题节奏、作息稳定。

真实限时测验优先于日期标签。若基础断层仍决定总分，即使进入真题阶段，也给它一个受限的修补窗口；不要重新展开整本课程。

## 主要矛盾的选择

先在科目层考虑可得分空间、考试权重、重复错误、前置影响、证据可信度和达标成本；再在主攻科目内比较专题权重、未掌握比例、重复错误和证据质量。没有成本或可靠测验时，只说“暂定主攻”，不要把启发式小数描述成科学精确值。

计划必须有：一个周主攻、最多两个维持方向、当日容量、15% 缓冲、检查点日期和触发重排的条件。
