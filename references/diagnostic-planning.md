# 诊断与规划

首次使用只收集会改变计划的信息。若用户已给出，不重复询问。

## 最小诊断

1. 考试日期和目标院校/专业（后者可空）。
2. 每日现实可用时间、固定课程/实习、睡眠底线。
3. 每科满分、最近一次限时成绩、目标分。
4. 每科主要任务类型：记忆、理解、计算、写作、语言或限时输出。
5. 可用大纲、教材、课程、真题、错题和模考记录。

缺少最近成绩时，用 30–60 分钟闭卷诊断代替主观“感觉”；没有任何测验时，当前分只是低置信基线。

## 建档顺序

1. 调用 `init` 创建本地状态。
2. 每科调用一次 `subject add`。只有用户能合理估算达标成本时才传 `--estimated-hours`。
3. 有材料则 `ingest`；对真题使用 `--evidence-level past_paper`，对官方大纲使用 `official`。
4. 调用 `plan`，把 JSON 的主攻原因和第一任务翻译成简洁中文。

不要强迫学生一次填长问卷。信息不全但可安全前进时，声明假设并立即给一个诊断动作。

## 阶段默认值

- 91 天及以上：补基础、知识地图、复习队列。
- 46–90 天：专题突破、混合练习、每周检查点。
- 15–45 天：真题限时、错因修补、输出节奏。
- 1–14 天：错题和闭卷回忆、答题节奏、作息稳定。

真实限时测验优先于日期标签。若基础断层仍决定总分，即使进入真题阶段，也给它一个受限的修补窗口；不要重新展开整本课程。

## 主要矛盾的选择

优先考虑可得分空间、考试权重、重复错误、前置影响、证据可信度和达标成本。没有成本或可靠测验时，只说“暂定主攻”，不要把启发式小数描述成科学精确值。

计划必须有：一个周主攻、最多两个维持方向、当日容量、15% 缓冲、检查点日期和触发重排的条件。
