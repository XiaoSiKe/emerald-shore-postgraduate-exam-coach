# PRD：青岸计划·考研冲刺教练 V0.5.0

## 产品形态

青岸计划首先是一个对话驱动的 Agent Skill，而不是独立 App、题库网站或要求学生学习命令的 CLI 产品。`SKILL.md` 与按需加载的 `references/` 决定教练行为；本地 Python 引擎只负责把跨会话证据可靠地保存下来。

学生使用自然语言进入诊断、训练、复盘或情绪降阶。Skill 在后台调用引擎，并把结构化结果翻译为简洁中文，不默认暴露命令和原始 JSON。

## 问题

冲刺阶段的大学生通常同时面对范围大、科目多、时间估算失真、被动学习、错题不回流和焦虑拖延。普通学习计划容易平均分配、排得过满，并在第一次失约后失去价值。

## 用户与任务

主要用户是距离硕士研究生招生考试初试约 1–4 个月、需要在多科与大量专题之间取舍的大学生。系统也适配应届、跨考、二战和边实习边备考的人，不预设学校、专业、科目组合或基础水平。他们需要持续知道：哪门科目是主要矛盾、哪个专题是最小突破口、今天在现实校园节律下能做什么、如何证明学会、什么结果会改变计划。

## 产品承诺

- 依据真实分数、科目与专题权重、错因、证据可信度和可用时间确定主攻方向。
- 用哲学策略闭环组织“调查—矛盾—集中—实践—校正—阶段”，不做人物扮演或口号堆砌。
- 用执行、有效证据、独立答题、错因复发和检查点评估效率，不生成综合效率分。
- 区分工作日与周末，把上课、实验、实习、通勤、睡眠和地点纳入现实容量。
- 用目标院校、专业、科目代码、材料类型与年份约束公开资料的证据强度。
- 先建立科目—章节—专题—来源题骨架，再生成能直接闭卷、自测和纠错的专题卡。
- 每天最多三个关键任务并预留缓冲。
- 用闭卷回忆、限时题和输出结果代替熟悉感。
- 保留材料来源，拒绝无证据押题。
- 执行率或成绩变化后重排，而不是维护失真的旧计划。
- 来源题一次一题，作答结果回流专题掌握度和复习队列。
- 每周完成计划、执行监控、证据反思；启动困难时使用具体 if–then 触发。
- 讲解先给准确本质，再给有边界的生活类比，最后要求学生复述或做题。
- 情绪价值通过自主选择、胜任证据和合作关系落到现实下一步；幽默亲和但不嘲笑学生。

## 非目标

- 不提供目标院校录取保证、分数保证或押题率。
- 不内置某一科目的完整课程内容。
- 不替代官方招生信息、教师、医生或心理咨询。
- 不上传、分享或遥测用户学习资料。

## 核心旅程

1. 用户用自然语言说明当前目标或困难；Skill 复用已有信息，一次只补一个会改变计划的关键未知。
2. Skill 在后台初始化或读取本地状态，记录目标院校/专业与校园节律，再选择冲刺阶段。
3. 用户按科目代码和章节建立高价值专题，并用大纲/真题标注权重与证据置信度。
4. 用户导入材料；系统先判断归类置信度，再生成来源记录、来源题和可检索文本。
5. 系统确定周主攻科目与专题，生成不超容量的今日任务和启动协议。
6. 用户逐题或限时训练，记录时间、结果和错因；结果更新专题掌握度和复习队列。
7. `efficiency` 分析执行、有效证据、答题质量、错因复发和检查点，学生先解释数据，Skill 再补充判断。
8. `weekly` 汇总证据与效率诊断，决定下周保留、削减与主攻，并让学生设置一个学习策略目标。
9. 用户始终得到一个通俗、亲和但准确的下一动作和可观察完成信号；本地引擎不可用时，会明确说明结果尚未持久化。

## 成功指标

V0.5.0 不收集遥测。通过本地测试和用户自愿反馈观察：成功初始化/迁移率、校园节律建档率、专题建档率、来源匹配记录完整率、效率评估使用率、来源题作答率、周复盘率、重复错因下降、重排后执行率，以及虚构来源/押题投诉为零。

## 验收

不同学校、专业、备考身份和六类能力科目可进入同一工作流；工作日/周末容量按校园节律变化；目标院校公开资料缺少匹配依据时被拒绝；低置信材料不能直接绑定；题目在作答前无答案字段；错误会改变专题掌握度并进入复习队列；效率评估不产生综合分；V0.1 数据无损迁移且旧目录保留；V0.2–V0.4 工作区继续兼容运行。
