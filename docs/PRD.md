# PRD：青岸计划 · Emerald Shore Initiative V0.3.0

## 产品形态

青岸计划首先是一个对话驱动的 Agent Skill，而不是独立 App、题库网站或要求学生学习命令的 CLI 产品。`SKILL.md` 与按需加载的 `references/` 决定教练行为；本地 Python 引擎只负责把跨会话证据可靠地保存下来。

学生使用自然语言进入诊断、训练、复盘或情绪降阶。Skill 在后台调用引擎，并把结构化结果翻译为简洁中文，不默认暴露命令和原始 JSON。

## 问题

冲刺阶段的大学生通常同时面对范围大、科目多、时间估算失真、被动学习、错题不回流和焦虑拖延。普通学习计划容易平均分配、排得过满，并在第一次失约后失去价值。

## 用户与任务

主要用户是距离硕士研究生招生考试初试约 1–4 个月、需要在多科与大量专题之间取舍的大学生。他们需要持续知道：哪门科目是主要矛盾、哪个专题是最小突破口、今天做什么、如何证明学会、什么结果会改变计划。

## 产品承诺

- 依据真实分数、科目与专题权重、错因、证据可信度和可用时间确定主攻方向。
- 每天最多三个关键任务并预留缓冲。
- 用闭卷回忆、限时题和输出结果代替熟悉感。
- 保留材料来源，拒绝无证据押题。
- 执行率或成绩变化后重排，而不是维护失真的旧计划。
- 来源题一次一题，作答结果回流专题掌握度和复习队列。
- 每周完成计划、执行监控、证据反思；启动困难时使用具体 if–then 触发。
- 情绪支持落到现实可启动的下一步。

## 非目标

- 不提供目标院校录取保证、分数保证或押题率。
- 不内置某一科目的完整课程内容。
- 不替代官方招生信息、教师、医生或心理咨询。
- 不上传、分享或遥测用户学习资料。

## 核心旅程

1. 用户用自然语言说明当前目标或困难；Skill 复用已有信息，一次只补一个会改变计划的关键未知。
2. Skill 在后台初始化或读取本地状态并选择冲刺阶段。
3. 用户在科目下建立高价值专题，并用大纲/真题标注权重与证据置信度。
4. 用户导入并绑定材料；系统生成来源记录、来源题和可检索文本。
5. 系统确定周主攻科目与专题，生成不超容量的今日任务和启动协议。
6. 用户逐题或限时训练，记录时间、结果和错因；结果更新专题掌握度和复习队列。
7. `weekly` 汇总执行率、证据次数和错误分布，决定下周保留、削减与主攻。
8. 用户始终得到一个明确下一动作和可观察完成信号；本地引擎不可用时，会明确说明结果尚未持久化。

## 成功指标

V0.3.0 不收集遥测。通过本地测试和用户自愿反馈观察：成功初始化/迁移率、专题建档率、来源题作答率、周复盘率、重复错因下降、重排后执行率，以及虚构来源/押题投诉为零。

## 验收

四门不同类型科目和多个专题可进入同一工作区；题目绑定科目/专题且答题前无答案字段；错误会改变专题掌握度并进入复习队列；周复盘从真实账本生成；V0.1 数据无损迁移且旧目录保留；原有容量、检查点、PDF 降级和结构化错误行为继续通过。
